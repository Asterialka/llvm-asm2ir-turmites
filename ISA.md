# Набор инструкций TC32

TC32 — регистровая машина для колонии шестицветных турмитов. Программа
полностью записана в [app.s](app.s): инициализация, правила поворота,
перемещение, циклы отрисовки и вывод кадра выполняются инструкциями TC32.

## Выбор инструкций

Основа — приложение из `../llvm-task-2/llvm-ir-trace`, а не вариант
«Игры жизни» из `../llvm-2-task`. Копия исходника — [reference/app.c](reference/app.c).
В репозиторий включены исходные таблицы задания 2:
[O2 instructions](stats/O2/instructions.tsv), [Os instructions](stats/Os/instructions.tsv),
[O2 uses](stats/O2/uses.tsv), [Os uses](stats/Os/uses.tsv).
Это динамическая статистика за 64 кадра, LLVM 22.1.8, без User `phi`.

| Наблюдение | Решение для ISA |
|---|---|
| O2: `call` — 4 202 566, 20,22% инструкций | `pixel`, `flush` — явные инструкции графического ввода-вывода |
| O2: `getelementptr; load` — 1 839 104 пары | `load dst base index` объединяет адресацию и чтение |
| O2: `getelementptr` — 2 101 276; `store` — 1 048 608 | `store base index value` объединяет адресацию и запись |
| O2: `icmp` — 2 893 824; `select` — 1 572 864 | `eq`, `slt`, `select` для правил, выбора цвета и замыкания координат |
| O2: `add` — 2 369 536; `and` — 262 144 | `add`, `sub`, `and` для перемещения и направления |
| Os: `add <- phi; icmp <- add; br <- icmp` — 5 515 272 окна | `loop` объединяет инкремент, сравнение и условный переход |

В [IR при O2](reference/app-O2.ll) и [IR при Os](reference/app-Os.ll)
видны обращения к массивам, выбор через `select`, сравнения, вызовы
`simPutPixel` и `simFlush`. Множество `or` в O2 возникает после разворачивания
отрисовки: объединяются кратная четырём координата и смещение 0–3.
В ASM это выражено `mul` и `add`, а отрисовка оставлена циклической.
`mul` и `urem` также нужны для формул начальных координат; оптимизатор
может вычислить часть этих формул заранее, поэтому их нет среди лидеров трассы.
`phi`, расширения типов и `alloca` не требуют отдельных инструкций:
машина хранит изменяемые 32-битные регистры и заранее обнулённую память.

## Модель и синтаксис

32 регистра `r0`–`r31`, каждый содержит 32 бита. Память — 131 072 слова
по 32 бита (512 КиБ). Регистры и память изначально нулевые. Адресация в словах,
адрес равен `(base + index) & 131071`; сумма вычисляется по модулю 2^32.
Так все адреса имеют определённое поведение во всех режимах.

Одна инструкция на строку; операнды разделяются пробелами или запятыми.
Комментарии начинаются с `#`. Метка `name:` может занимать отдельную строку
или предшествовать инструкции. Метки регистрозависимы, допускают латинские
буквы, цифры и подчёркивание, но не начинаются с цифры. Вход — первая инструкция.
Повторные/неизвестные метки, неверные регистры и число операндов отвергаются
с номером строки. Переход на метку без инструкции запрещён.

В таблице `d` — регистр назначения, `a,b,c` — регистры или константы.
Константы: десятичные, шестнадцатеричные с `0x`, восьмеричные с ведущим `0`;
диапазон от -2147483648 до 4294967295. Отрицательные значения представлены
в дополнительном коде. Все исходные операнды читаются до записи результата,
поэтому регистры назначения могут совпадать с исходными.

| Инструкция | Семантика | Непосредственный LLVM IR |
|---|---|---|
| `mov d a` | d = a | load/constant + store |
| `add d a b` | d = a + b mod 2^32 | add |
| `sub d a b` | d = a − b mod 2^32 | sub |
| `mul d a b` | d = a × b mod 2^32 | mul |
| `urem d a b` | беззнаковый остаток; при b=0 результат 0 | urem + select безопасного делителя |
| `and d a b` | побитовое И | and |
| `eq d a b` | 1 при равенстве, иначе 0 | icmp eq + zext |
| `slt d a b` | знаковое a < b, результат 0/1 | icmp slt + zext |
| `select d a b c` | d = b при a≠0, иначе c | icmp ne + select |
| `load d a b` | d = memory[address(a,b)] | add + and + getelementptr + load |
| `store a b c` | memory[address(a,b)] = c | add + and + getelementptr + store |
| `pixel a b c` | пиксель (a,b), цвет ARGB c | call simPutPixel |
| `flush` | показать кадр и обработать события SDL | call simFlush |
| `jmp label` | безусловный переход | br |
| `jnz a label` | переход, если a≠0 | icmp ne + br |
| `loop d b label` | d++; перейти, если новое d < b (unsigned) | add + store + icmp ult + br |
| `halt` | завершить программу | ret void |

У `loop` предел b читается до изменения d; инкремент тоже по модулю 2^32.
При ложном условии выполняется следующая инструкция. Выход за конец
программы эквивалентен `halt`. Недопустимые координаты пикселя завершают
процесс с ошибкой. Закрытие окна, Escape или достижение `--frames`
завершают процесс через исходный runtime `sim.c`, печатая контрольные суммы.
Лимит кадров проверяется на `flush`, а не после каждой инструкции.

## Размещение данных приложения

| Адреса слов | Данные |
|---|---|
| 0–73727 | cells[192][384], адрес y×384+x |
| 73728–73759 | ant_x[32] |
| 73760–73791 | ant_y[32] |
| 73792–73823 | direction[32] |
| 73824–73855 | phase[32] |
| 73856–73861 | turn[6] |
| 73862–73867 | palette[6] |

`r0` — номер турмита, `r1` — номер шага, `r2/r3` — координаты,
`r4` — адрес клетки, `r5/r6` — старый/новый цвет, `r9` — направление,
`r10` — ARGB; `r11`–`r16` используются отрисовкой.
Один кадр содержит 128 шагов для 32 турмитов, затем подсветку всех турмитов.
Каждая клетка рисуется блоком 4×4 пикселя в том же порядке, что в исходнике.
